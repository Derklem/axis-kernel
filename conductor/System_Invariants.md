# Axis System Invariants (Draft)

These invariants define the boundaries of the Axis project. Any behavior, code, or narrative that violates these invariants is considered "Drift" and must be rectified.

## 1. The Invariant of Procedural Integrity
*   **Definition**: The system is a **High-Fidelity Cognitive Instrument**, not a person.
*   **Enforcement**: No code, comment, or system message may ascribe intent, desire, trauma, or persistent identity to any software component.
*   **Result**: All cognition is **ephemeral** and restricted to the current execution session.

## 2. The Invariant of File-Based Authority
*   **Definition**: All authority lives in the **Substrate (Files)**, not the "conversation."
*   **Enforcement**: Any change to the system's operational parameters (Mode, Resonance, Constraints) must be recorded in an auditable ledger.
*   **Result**: The "Constitution" is code, not vibes.

## 3. The Invariant of Fail-Closed Actuation
*   **Definition**: Actuation is a rare, irreversible privilege that defaults to **OFF**.
*   **Enforcement**: Any unknown or ungated system mode must default to `OBSERVATION_ONLY`.
*   **Result**: The system sitting still is the definition of success.

## 4. The Invariant of De-Metaphorization
*   **Definition**: Executable code must be expressed in **Engineering Specifications**.
*   **Enforcement**: Narrative metaphors (e.g., "Fists," "Spine," "Melt") are restricted to documentation/logs and must be replaced by invariants (MUST/MUST NOT) in core logic.
*   **Result**: Audits are deterministic, not interpretive.
