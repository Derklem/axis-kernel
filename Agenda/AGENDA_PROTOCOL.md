# Agenda Protocol

The Agenda engine converts a pool of opaque `hypothesis_candidates` and deterministic state/strategy roots into a ranked, strictly-capacity-constrained sequence of executable actions (an `agenda`).

## Authority
Agenda owns the `agenda.json` schema and its output artifact. It relies entirely on Strategy and State to authorize what is *allowed*, and acts solely to prioritize what is *most valuable* relative to cost.

## Normative Prohibitions
1. **No Authoritative Projection**: Agenda must not copy or re-implement State or Strategy schemas. It consumes opaque canonical roots for external objects.
2. **No Side Effects**: Agenda never executes experiments, mutates state, or generates observations.
3. **No Overrides**: Agenda cannot change Strategy decisions or invent new candidates not provided in the `planner_input`.
4. **No Float Arithmetic**: All scoring and weighting must use deterministic integers.
5. **No Non-determinism**: Agenda must not read the system clock, use random numbers, or rely on non-lexical sorting.
6. **No Implicit Defaults**: If constraints or candidates are malformed, it must fail loudly, not guess.

## Priority Resolution
Sorting is determined by calculating a composite integer score for each candidate:
`Score = (expected_information_gain * gain_weight) - (estimated_compute_cost * compute_cost_weight) - (estimated_attention_cost * attention_cost_weight)`

Candidates are ranked descending by `Score`. In the event of a tie, lexical ordering of the `candidate_id` breaks the tie (ascending).

## Capacity Restrictions
Agenda must strictly respect `max_agenda_items`, `max_compute_budget`, and `max_attention_budget`.
If admitting the next highest-scoring candidate would breach ANY capacity limit, that candidate is classified as `DEFERRED` (or `REJECTED` if it exceeds the limit by itself).

## Output Identity (`agenda_root`)
The Agenda engine issues a deterministic, self-identifying artifact. The `agenda_root` is generated by:
1. Constructing the complete Agenda output payload (omitting the `agenda_root` field).
2. Generating a canonical hash (SHA-256 over normalized JSON).
3. Appending the hash as `agenda_root` inside the payload.
This allows downstream systems to refer to a precise Agenda artifact rather than merely its inputs.
